# `model-test/src/test/java/hu/blackbelt/judo/meta/query` — dual-engine validation test harness (EVL vs Java) and its benchmark

| File | Purpose |
|---|---|
| `AbstractQueryValidationTest.java` | Shared JUnit fixture inherited by the dual-engine validation tests. `@BeforeEach` builds `queryModelSupport` over `urn:Query.model` and `queryModel` named `test`, both empty. Exports protected `runValidation(ValidatorType, expectedErrors, expectedWarnings)` and `runValidationExpectingNoIssues(ValidatorType)`; EVL branch calls `QueryEpsilonValidator.validateQuery` under `BufferedSlf4jLogger`, JAVA branch calls `QueryValidator.validateQuery`. Subclasses must add model content themselves after `setUp`. Unknown enum constant throws `IllegalArgumentException`; failures are logged (expected / unexpected / not-found sets) and rethrown, never swallowed. |
| `QueryValidationPerformanceTest.java` | Benchmarks EVL against Java validation on a synthetic model: `SELECT_COUNT=200` `Select`s, `JOINS_PER_SELECT=5` `SubSelectJoin`s, `FEATURES_PER_SELECT=3` `Filter`s, built through `QueryBuilders` and pushed via `queryModelSupport.addContent`. Exports `benchmarkEvlVsJavaValidation()`; 1 warmup plus 3 measured rounds each for EVL, Java sequential, Java parallel, logging avg/min/max plus speedup ratios. Asserts nothing — validation exceptions are deliberately caught, so it fails only when model building or context wiring breaks. |
| `ValidatorType.java` | Enum selecting the validation engine for `@EnumSource(ValidatorType.class)` parameterized tests. Constants `EVL` (Epsilon script path) and `JAVA` (judo-zeta path). `AbstractQueryValidationTest.runValidation` switches on it, so a constant added here without a matching branch fails at runtime with `IllegalArgumentException`. |
